# Roadmap

Priorities are ordered by the evidence they would add. Historical phase numbers are preserved in the status register rather than reused as a claim about the current runtime.

| Priority | Milestone | Completion evidence |
| --- | --- | --- |
| 1 | Re-establish the current application baseline | Known revision, clean dependency record, reproducible test command and result |
| 2 | Make dashboard data sources explicit | Separate simulation/hardware labels, backend timestamps, and stale indicators |
| 3 | Record a complete one-node path | Firmware, decoded receiver record, matching UI value, and disconnect/reconnect behavior |
| 4 | Validate simultaneous nodes | Distinct logical identities, independent freshness, and measured loss/recovery |
| 5 | Consolidate operator tooling | Documented startup/shutdown, configuration validation, and reproducible recovery |
| 6 | Harden service access | Restricted listeners, broker authorization, authenticated API access where needed, and reviewed logs |
| 7 | Integrate permission-controlled agent workflows | Demonstrated approval, cancellation, audit, and no unintended external action |
| 8 | Expand sensing research | Controlled ground-truth trials with reported limitations and error rates |

Voice interfaces, retrieval-augmented generation, expanded agent departments, multi-room fusion, and physiological sensing remain separate research tracks until their inputs, outputs, and validation are documented.

The next useful milestone is a reproducible integration record, not a larger dashboard counter or an unverified feature list.
